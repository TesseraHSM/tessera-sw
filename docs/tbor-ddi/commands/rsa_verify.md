# RsaVerify (`0x36`)

Verifies an RSASSA-PSS or RSASSA-PKCS1-v1_5 signature over the raw message
referenced by an OOB input SGL descriptor. The device authenticates and
unmasks the caller-held RSA private-key envelope, derives its public
`n || e` on-device, hashes the message internally, and verifies the
signature. Neither public components nor private key bytes are returned.
This is distinct from raw `RsaModExp` and padded `RsaEncryptDecrypt`.

The command requires an active CO or CU session and the masked key's `verify`
usage permission. The envelope determines whether the key is RSA-2048, -3072,
or -4096 and whether it is CRT or non-CRT.

## Request fields

| Field | Wire form | Description |
|---|---|---|
| `session_id` | `u16` | Active CO/CU session. |
| `masked_key` | aligned bytes, max 3168 | Authenticated masked RSA private-key envelope. |
| `padding` | `u8` | `0`: PSS; `1`: PKCS#1 v1.5. |
| `hash_algo` | `u8` | Required for either padding: `1`: SHA-256, `2`: SHA-384, `3`: SHA-512. |
| `salt_len` | optional `u16` | Required for PSS, including explicit zero; forbidden for v1.5. |
| `message_index` | `u8` | Index of the raw message's input SGL descriptor. |
| `message_len` | `u16` | Raw message length, 0 through 8192 inclusive. |
| `signature` | inline bytes, max 512 | Exactly 256, 384, or 512 bytes for the key's modulus. |

PSS uses MGF1 with the selected hash and trailer field 1 (`0xBC`). Verification
enforces the exact supplied salt length. Its maximum is
`emLen - digest_len - 2`, where `emBits = modulus_bits - 1` and
`emLen = ceil(emBits / 8)`. PSS salt bytes are generated by the signer, never
sent in this request. PKCS#1 v1.5 checks the selected hash's DigestInfo.

For an empty message, `message_index` must be zero and no OOB descriptor is
read. For nonempty messages, a direct Data Block descriptor's length must
equal `message_len`. On Uno, Segment/Last Segment descriptors are submitted
unchanged to GDMA; hardware walks the SGL and gathers `message_len` bytes.
Firmware does not walk SGLs or PRPs. The scoped DMA allocation is exactly
`message_len` bytes, at most 8192, within the existing per-IO heap, and is
released after hashing and before RSA execution.

## Response and OOB lifetime

Success has an empty response body. A well-formed invalid signature returns
`RsaVerifyFailed` (`0x0870010E`); malformed parameters, key authentication,
scope, permission, and operational failures retain their distinct statuses.
The signature is in device operand order: little-endian on Uno/std Uno and
big-endian on std Duo.

The host must keep the message buffer unchanged and accessible until command
completion. Capturing the descriptor once does not atomically snapshot the
referenced bytes; verification covers the byte stream actually read. Session
sealing does not extend its guarantees to OOB contents.
